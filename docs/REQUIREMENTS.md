# LLM 接口可用性监测工具 —— 需求文档

> 版本：v0.2（可用性优先，评审修订稿）
> 状态：待最终评审
> 文档对象：产品 / 研发 / 测试

---

## 1. 背景与目标

### 1.1 背景
在生产或评估过程中，需要对接多个模型供应商的接口（OpenAI、DeepSeek、各类中转、自托管 vLLM 等）。这些接口可能出现连接失败、超时、限流或流式响应中断，需要一个**统一、可量化、持续**的监测手段，评估指定接口与模型是否能够稳定响应。

### 1.2 目标
构建一个**以接口可用性监测为主、响应速度为辅**的本地工具，能够：

1. 对指定的 **OpenAI 兼容**接口与模型进行**周期性单请求流式探测**；
2. 判断请求能否在设定时限内返回符合协议的有效文本，并记录成功、超时或错误原因；
3. 展示最近一次探测结果、结果新鲜度，以及时间窗内的**成功率、超时率、错误率和样本数**；
4. 以 **TTFT、总耗时**辅助观察响应速度，不将复杂性能指标作为 MVP 的前提；
5. 提供**本地 Web 面板**查看当前状态与历史记录；
6. **跨平台、无外部运行依赖、低门槛**：按平台分发单文件可执行程序，适合 Windows 单机环境。

### 1.3 评估边界
- 监测对象是**接口地址 + 模型**，不是供应商整体；同一供应商的不同模型分别配置。
- 结果代表**运行工具的机器到被测接口的端到端体验**。本机网络、DNS、代理等问题也可能导致失败，不能将所有失败直接归因于供应商。
- 成功率指**实际探测请求的成功比例**，不是供应商真实在线时长比例或严格的 SLA 结论。周期采样可能漏掉两次探测之间的短暂故障。
- 工具仅在进程运行、机器可用时探测；程序退出或机器休眠期间不产生样本，也不推断接口可用或不可用。

### 1.4 非目标（MVP 不做）
- 不评估回答正确性、模型能力或模型身份，不做语义质量打分；
- 不做并发压测、RPS 吞吐评测、TPS、token 估算、P50/P95/P99 或排名（2026-10-09 修订：基于服务端 usage 上报的 decode/prefill 吞吐为对象级可选指标，见第 3.1 节与决策 #11，不属于估算）；
- 不做工具调用、多模态等响应形态的探测；第一版仅测试文本生成；
- 不做自托管推理引擎（不替代 vLLM 等）；
- 不做多协议解析（第一版仅 OpenAI 兼容 `chat/completions`）；
- 不做推送告警、CSV/JSON 导出、局域网开放、权限系统、多租户或多机采集。

## 2. 目标用户与使用场景

| 用户 | 场景 |
|------|------|
| 算法 / 平台工程师 | 观察指定接口与模型的请求成功情况，辅助接口选型 |
| 运维 / 质量保障 | 持续查看接口状态，定位超时、限流、鉴权失败或响应中断 |
| 产品评估人员 | 直观查看近期是否可用、是否稳定，以及响应是否较慢 |

**典型流程**：下载对应平台的单文件 → 双击启动 → 浏览器打开面板 → 添加监测对象（填写 base_url/key/model）→ 后台定时探测 → 查看当前状态、历史成功比例与失败原因。

## 3. 可用性与指标口径

### 3.1 核心指标

| 指标 | 定义 | 单位 / 展示要求 |
|------|------|-----------------|
| **最近一次探测结果** | 当前监测目标最近一次有效定时探测的最终结果 | 成功 / 超时 / 错误，并显示完成时间 |
| **成功率** | 成功探测数 / 纳入统计的探测总数 | %，同时展示成功数 / 总样本数 |
| **超时率** | 首内容超时或总超时的探测数 / 纳入统计的探测总数 | %，区分两种超时 |
| **错误率** | 非超时失败探测数 / 纳入统计的探测总数 | %，可查看具体原因 |
| **TTFT（首内容延迟）** | 从开始发起 HTTP 请求到解析出第一个非空文本内容增量的耗时 | ms；未收到内容时为空 |
| **总耗时** | 从开始发起 HTTP 请求到成功结束或失败终止的耗时 | ms；失败耗时不解释为成功响应延迟 |
| **decode 吞吐** | `(completion_tokens-1)/(总耗时-TTFT)`，仅 ok 样本、token 数来自服务端 usage 上报 | tok/s；对象开启吞吐开关且有 usage 时展示 |
| **prefill 吞吐** | `prompt_tokens/TTFT`，含排队等待，为近似下界 | tok/s；同上，展示时标注"近似" |

### 3.2 成功与流式结束判据
- 请求使用 `stream: true`，探测一个文本回复；首内容以完整 SSE 事件中 `choices[0].delta.content` 的非空字符串为准。
- 角色事件、空 delta、心跳、usage 和结束标记均**不算首内容**；TTFT 与首内容超时使用同一判据。仅有 reasoning 或工具调用字段不满足本版文本探测条件。
- 成功必须同时满足：**HTTP 成功响应、在超时限制内收到非空有效文本、无协议或流内错误、满足正常结束条件**。
- 正常结束接受 `[DONE]`；对于不发送 `[DONE]` 的兼容端点，接受**已收到非空 `finish_reason` 后正常 EOF**。仅有 EOF、没有任何正常结束证据，记为 `aborted`，即使此前已经收到部分文本。
- 达到 `max_tokens` 后正常结束（如 `finish_reason=length`）可以算成功；文本的语义质量不是成功判定条件。
- 正常结束但无有效文本，记为 `empty`；HTTP 200 中的流内错误不能算成功。
- 默认不请求 `stream_options.include_usage`；对象级开关（`include_usage`）开启时请求，token 数仅取服务端 usage 事件上报值，不做字符或 delta 估算；usage 缺失或接口主动附带 usage 均不影响可用性判定，主动附带的 usage 照常记录。MVP 不基于估算计算 TPS。
- 请求开始、首内容与结束之间的耗时使用单调时钟计算，包含连接、网络往返、排队和生成等端到端时间。

### 3.3 最终结果分类

| status | 含义 | 统计归属 |
|--------|------|----------|
| `ok` | 满足成功判据 | 成功 |
| `timeout_ttft` | 首内容期限到达，仍未收到有效文本 | 超时 |
| `timeout_total` | 总期限到达，探测仍未正常完成 | 超时 |
| `http_error` | HTTP 非 2xx 响应 | 错误 |
| `conn_error` | DNS、连接、TLS 等失败，且不是探测期限导致的超时 | 错误 |
| `stream_error` | HTTP 成功响应中的流内错误 | 错误 |
| `protocol_error` | 非预期响应格式、无法解析的事件或无效协议数据 | 错误 |
| `empty` | 正常结束，但无非空有效文本 | 错误 |
| `aborted` | 流异常断开，或 EOF 时缺少正常结束证据 | 错误 |
| `cancelled` | 程序退出、停用或编辑配置导致的主动取消 | 不纳入可用性统计 |

- 每次实际发起的探测只记录一个最终结果，`success` 当且仅当 `status=ok`。
- 首内容计时只在首次有效文本到达前生效；总超时覆盖完整请求，两者从同一个请求开始时刻起算。
- 两个期限先到者决定超时类型；若同时到期且仍无首内容，固定归为 `timeout_ttft`。探测期限导致的底层错误优先归为对应超时，不能记为连接错误。
- TTFT 已测得后发生错误或总超时，保留 TTFT，但最终结果仍为失败。

### 3.4 统计样本与时间窗
- 默认统计仅包含**已经完成、实际发起、非主动取消的定时探测**；手动测试单独标记，不改变默认成功率和监测状态。
- 运行中的请求、跳过的调度、停用期间、程序未运行期间均不进入分母；不得自动补成成功或失败样本。
- 时间窗按请求开始时间筛选，支持 `1h / 24h / 7d`；默认只统计当前目标版本，历史版本单独查询。
- 成功、超时、错误三类互斥且穷尽有效样本，满足：**成功率 + 超时率 + 错误率 = 100%**（展示四舍五入可能有微小差异）。
- 无有效样本时，各比例返回空值、面板显示“暂无样本”，不能显示 0% 或 100%。
- 趋势按时间桶汇总，同时提供样本数；无样本的桶留空，不插值为正常，不将失败耗时混入成功响应耗时统计。

## 4. 功能需求

### 4.1 配置管理
- [ ] 在网页上**添加 / 编辑 / 删除 / 启用停用**监测对象（provider）。
- [ ] 配置字段：名称、Base URL、API Key、模型名、探测提示词、`max_tokens`、总超时、首内容超时、首内容慢阈值、探测间隔、是否启用。
- [ ] Base URL 明确为 API 前缀，例如 `https://example.com/v1`；去掉尾部 `/` 后追加 `/chat/completions`，不自动猜测或重复追加 `/v1`。
- [ ] 使用 Bearer API Key；允许无需鉴权的自托管接口留空。不跳过 HTTPS 证书校验。
- [ ] 默认提示词约 64 字符，要求简短纯文本回复；`max_tokens=128`、探测间隔 5 分钟。
- [ ] MVP 超时默认值：首内容 10 秒、总超时 60 秒；首内容慢阈值默认 2 秒，仅作速度提示，以上均可按对象修改。
- [ ] 配置校验：`max_tokens>0`，`0<慢阈值<首内容超时≤总超时`；探测间隔为 0（仅手动）或至少 1 分钟。页面以分钟 / 秒展示，存储采用第 9 节约定的单位。
- [ ] 配置持久化，重启后保留。Base URL 或模型改变时递增目标版本；新版本的状态和统计不混入旧目标数据，旧版本历史仍可查。
- [ ] 修改正在使用的配置时，先取消该对象的在途请求，再按新配置调度；取消不计为接口故障。
- [ ] 删除对象前确认；删除配置及对应历史，停止后续调度，不影响其他对象。

### 4.2 探测引擎
- [ ] 发送 OpenAI 兼容的流式 `chat/completions` 文本请求，按第 3 节规则计算 TTFT、总耗时并分类。
- [ ] 支持手动测试一次与后台定时探测；多个对象独立调度，一个失败不影响其他对象。
- [ ] MVP **不自动重试**、不做并发压测，不为获取 usage 发起额外请求，避免隐藏首次失败或增加费用。
- [ ] 错误明细记录 HTTP 状态码及脱敏后的原因；服务端返回的错误内容不作为可信指令或 HTML 执行。
- [ ] 单个对象的并发与错过调度按第 7 节执行。

### 4.3 Web 面板
- [ ] **概览**：名称 / 模型、监测状态、最近一次定时探测结果与时间、时间窗内成功数 / 总样本数、成功率、超时率、错误率。
- [ ] **详情**：TTFT、总耗时、探测结果的简单历史趋势，以及可筛选的失败明细；性能分位数与排名不属于 MVP。
- [ ] 支持切换对象、当前 / 历史目标版本及 `1h / 24h / 7d` 时间窗。
- [ ] 当前状态与历史比例分开展示；结果过期、停用或无数据时，不得仅凭历史成功率显示为正常。
- [ ] 周期刷新状态；刷新只读取已有结果，不额外触发探测。

### 4.4 状态提示
- [ ] 仅在面板以**文字 + 状态色**提示，不做推送；具体状态与优先级见第 7 节。
- [ ] 成功但 TTFT 超过慢阈值时显示“可用，但首内容较慢”，仍计为成功，不与超时混淆。

### 4.5 历史数据
- [ ] 探测结果持久化；支持按对象、目标版本、时间窗和定时 / 手动来源查询明细。
- [ ] 支持有限条数和分页读取；不一次返回全部历史。
- [ ] CSV / JSON 导出列为后续增强，不纳入 MVP API 或验收。

### 4.6 手动测试
- [ ] “立即测试”发起一次调用，显示最终结果、TTFT、总耗时及长度受限的输出片段；不要求向浏览器实时转发完整流。
- [ ] 手动结果持久化，标记为 `manual`，不改变定时探测的默认统计和当前监测状态。
- [ ] 停用仅影响后台调度，仍可手动测试；同一对象已有在途请求时，提示“正在探测”，不再发起新请求。

## 5. 非功能需求

### 5.1 跨平台与无外部运行依赖
- [ ] **单一可执行文件**，无需安装 Go / Python 等运行时、依赖或 Docker。
- [ ] 支持 Windows / Linux / macOS，分别编译对应平台与架构的产物。
- [ ] 前端 HTML / JS / CSS 及所用资源内嵌于二进制，不依赖 CDN、外部字体或在线服务。
- [ ] 仅探测被测接口及其必要的网络连接时联网；离线时仍能查看已保存的历史和配置，但不能探测远端接口。

### 5.2 易用性
- [ ] 双击或一条命令启动，服务监听成功后自动打开浏览器；打开失败时显示可手动访问的实际 URL。
- [ ] 默认从端口 `10110` 开始，被占用时向后 `+1` 找空闲；`--port` 覆盖起始端口，无可用端口时给出明确错误。
- [ ] 数据存于当前用户可写的应用数据目录，不依赖可执行文件所在目录可写，避免在系统目录启动失败。

### 5.3 容量与数据保留
- [ ] 单节点支持 **至少 20 个监测对象**，每个最小探测间隔 1 分钟；不同对象可并行，每个对象最多一个在途请求。
- [ ] 默认每个对象保留最近 **20,000 条**结果（包含各版本及手动结果），上限可配，超出后裁剪最旧记录。
- [ ] 查询不得在每次刷新时重复全量扫描所有对象的历史；每次追加不得重写整个历史文件。
- [ ] 裁剪与追加协调执行，避免丢失新记录；不得长时间阻塞其他对象的探测或面板查询。

### 5.4 安全
- [ ] API Key **明文存于本地配置文件**（保留原确认决策）；使用当前用户目录并尽可能限制文件读取权限，不承诺抵御本机管理员访问。
- [ ] MVP 仅监听 `127.0.0.1`，不提供局域网开放或身份口令功能。
- [ ] 列表 / 配置读取接口不返回完整 API Key；页面仅显示是否已配置及掩码。编辑时未提供新 Key 表示保留原值，显式空值表示清除。
- [ ] API Key 不出现在日志、探测结果、错误明细或输出片段中；错误信息和输出片段限制长度并按文本展示。
- [ ] 不开放任意跨域访问；修改配置、删除和触发探测等接口校验同源请求，避免其他网页借本地服务操作配置或消耗探测费用。

### 5.5 健壮性
- [ ] 单对象失败不影响整个进程与其他对象。
- [ ] 数据文件损坏时保留原始数据、提示异常，尽可能恢复完整记录；允许跳过损坏行，不得直接清空全部历史重建。
- [ ] 平滑退出：停止新调度、取消在途请求、保存已完成结果；主动取消不计为接口故障。不承诺强制终止或断电时保留尚未完成的写入。
- [ ] 存储失败必须提示，不能伪装成接口错误或将未保存的数据宣称为已持久化。

## 6. 技术选型

| 维度 | 选择 | 理由 |
|------|------|------|
| 语言 | **Go** | 单二进制、跨平台构建、并发与流式 HTTP 支持 |
| 协议 | OpenAI 兼容 `chat/completions` | MVP 聚焦常见文本生成接口，不承诺兼容所有扩展参数 |
| 探测方式 | 流式 `stream: true` | 验证流式响应完整性，并测量首内容延迟 |
| 存储 | 本地配置文件 + **JSONL 追加记录** | MVP 轻量可分发；需满足裁剪、恢复与查询要求 |
| 前端 | 内嵌 HTML / JS / CSS，简单趋势展示 | 无外部资源依赖；可内嵌轻量图表库，不强制手写 canvas |
| 打包 | `go:embed` 前端 + 按平台构建 | 各平台分发一个可执行文件 |

> MVP 保留 JSONL，不提前建设复杂存储抽象；后续查询需求或容量超出基线时再评估 SQLite。使用内嵌第三方资源不影响用户侧“无需安装依赖”的目标。

## 7. 调度与监测状态

### 7.1 调度规则
- 程序启动或对象启用后，对启用且间隔大于 0 的对象立即探测一次，再按间隔定时触发；`interval_sec=0` 不自动触发。
- 同一对象的定时与手动请求共享一个在途限制；上一次未完成时跳过当前定时触发，不排队、不产生失败样本。
- 不补发程序停止或机器休眠期间错过的探测；恢复后继续调度，不集中补测。
- 停用或删除对象时取消其在途请求；配置编辑与取消规则见第 4.1 节。

### 7.2 状态优先级
按以下顺序判定；“正在探测”仅为附加提示，不覆盖停用、未知或结果过期状态。

| 优先级 | 状态 | 判定与展示 |
|--------|------|------------|
| 1 | **已停用** | `enabled=false`；不显示为接口不可用 |
| 2 | **仅手动** | 已启用但 `interval_sec=0`；显示手动结果，不宣称正在持续监测 |
| 3 | **未知** | 当前目标版本无有效的定时探测结果 |
| 4 | **结果过期** | 距离最近一次有效定时探测完成已超过 `2 × interval_sec + timeout_sec` 秒 |
| 5 | **可用** | 最新有效定时探测为 `ok`；TTFT 超过慢阈值时附加“首内容较慢” |
| 6 | **不可用：超时 / 错误** | 最新有效定时探测为对应失败类别，并展示具体原因 |

- 有效结果指已完成且非 `cancelled` 的定时探测；手动结果不能刷新定时结果的新鲜度。
- 当前状态不由历史成功率推导；例如历史成功率很高，但最新探测失败时仍显示不可用。
- 历史比例始终附带时间窗、样本数和目标版本，避免将稀疏或旧样本误解为实时结论。

## 8. 架构概览

```
被测 API（OpenAI 兼容）
        ▲ HTTP / SSE
        │
探测引擎 Engine ──结果──► 存储 Store（配置 / JSONL / 查询缓存）
        ▲                         │
        │ 调度 / 手动调用          │ 查询 / 统计
        └──── Server/API ◄────────┘
                   │ REST + 内嵌静态资源
                   ▼
              本地 Web 面板
```

- **Engine**：独立调度各对象，控制单对象在途请求，负责解析、计时及互斥分类。
- **Store**：持久化配置和结果，负责保留策略、恢复、按时间窗查询与统计。
- **Server/API**：本机 REST JSON 接口及内嵌前端；不依赖页面保持打开来维持探测。

## 9. 数据模型

### 9.1 providers

| 字段 | 类型 | 说明 |
|------|------|------|
| id | int | 稳定主键，删除后不复用 |
| name / base_url / api_key / model | string | 配置；Key 仅保存在本地，不由读取接口返回 |
| revision | int | 目标版本，初始为 1；Base URL 或模型改变时递增 |
| prompt / max_tokens | string / int | 文本探测请求参数 |
| timeout_sec / ttft_timeout_ms / ttft_slow_ms | int | 总超时 / 首内容超时 / 首内容慢阈值 |
| interval_sec | int | 0=仅手动；否则至少 60 |
| include_usage | bool | 是否请求 stream_options.include_usage 以计算吞吐；默认 false |
| enabled | bool | 是否启用定时调度 |
| created_at | int64 | UTC Unix 毫秒时间戳 |

### 9.2 results（JSONL 每行一条）

| 字段 | 类型 | 说明 |
|------|------|------|
| provider_id / revision | int | 关联监测对象及探测时的目标版本 |
| base_url / model | string | 探测时的目标快照，便于解释旧版本历史；不保存 Key |
| source | string | `scheduled` / `manual` |
| started_at / finished_at | int64 | UTC Unix 毫秒时间戳；时间窗按 started_at 筛选 |
| success | bool | 当且仅当 `status=ok` |
| ttft_ms | int64 / null | 首内容延迟；没有有效文本时为 null，不使用 0 或 -1 代替未知 |
| total_ms | int64 | 到正常结束或失败终止的耗时 |
| status | string | 第 3.3 节规定的最终类别 |
| http_status | int / null | 实际收到的 HTTP 状态码，未收到时为 null |
| error | string | 长度受限、脱敏后的错误详情；成功时为空 |
| output_preview | string | 长度受限的输出片段，用于手动测试回显；定时探测可不保存 |
| prompt_tokens / completion_tokens | int / null | 服务端 usage 事件上报的 token 数；未观测为 null，不参与成功判定 |

> 当前配置中的提示词、超时等参数调整可能改变探测行为；统计仅用于端到端可用性观察，不承诺不同参数下的严格性能对比。MVP 不保存完整回复；token 数仅为服务端 usage 上报的原始计数，不做字符或 delta 估算。

## 10. API 设计（草案）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/providers` | 配置摘要、当前监测状态及最近定时探测结果；不返回完整 Key |
| POST | `/api/providers` | 新增对象 |
| PUT | `/api/providers/{id}` | 更新配置；地址或模型变更时递增 revision |
| DELETE | `/api/providers/{id}` | 删除配置及对应历史，取消在途请求 |
| POST | `/api/providers/{id}/probe` | 手动探测一次并返回最终结果；已有在途请求时返回 409 |
| GET | `/api/stats?provider=&revision=&window=` | 成功 / 超时 / 错误数、样本数与比例；默认仅统计定时探测 |
| GET | `/api/series?provider=&revision=&window=` | 成功比例及成功请求耗时趋势，包含各桶样本数；无样本桶返回空值 |
| GET | `/api/results?provider=&revision=&window=&source=&limit=&before=` | 历史明细分页，可按来源筛选；before 为下一页游标 |
| GET | `/` | 内嵌面板 |

- 统计与趋势省略 revision 时使用当前版本；历史查询可显式选择旧版本或全部版本。
- 历史明细按时间倒序，游标需能区分时间戳相同的记录；limit 必须有服务端上限。
- 手动调用仅发起一次探测；服务端保存最终结果，不因浏览器等待超时而自动重试。取消规则仍按第 3 节执行。
- 导出接口不属于 MVP，后续按 CSV / JSON 同时补齐。

## 12. 验收标准

### 12.1 探测判定与统计（使用可控模拟接口）
1. 正常文本流按约定结束，记为 `ok`；达到 max_tokens 正常结束仍成功；缺少 usage 不影响判定。
2. 先发送角色或空事件、延迟发送文本：空事件不计 TTFT，也不能绕过首内容超时；TTFT 与模拟文本到达时间一致，允许测试环境约定的计时误差。
3. 首内容超时与输出中途总超时分别归类；同一请求只计一次失败，两个期限同时到期且无内容时归为 `timeout_ttft`。
4. HTTP 401 / 429 / 500 归为 `http_error`；HTTP 200 中的错误事件归为 `stream_error`；无效协议数据归为 `protocol_error`。
5. 已输出部分文本后异常断开，或无结束证据直接 EOF，归为 `aborted`；有 finish_reason 且正常 EOF 可成功；正常结束无文本归为 `empty`。
6. 测试数据包含 3 次定时成功、2 次定时超时、1 次定时错误、1 次主动取消和额外手动成功：默认分母为 6，成功率为 50%，超时率约为 33.33%，错误率约为 16.67%；取消和手动结果不影响比例。
7. 无有效样本时比例为空；当前状态为未知、停用、仅手动或结果过期时，不显示为正常，也不追加虚构失败记录。
8. 更换地址或模型后，当前版本状态从无样本开始，旧版本历史仍可查且不混入新版本统计。
9. `include_usage` 关闭时请求体不含 stream_options，行为与基线一致；开启时请求携带该参数且 usage 事件被记录；吞吐仅对携带 usage 的 ok 样本计算（decode 剔除 completion<2 与零 decode 时长样本，prefill 为含排队近似）；无 usage 证据时吞吐展示为空，不显示 0；旧数据（无新字段）加载与统计正常。

### 12.2 调度、持久化与部署
1. 定时与手动触发冲突时，同一对象最多一个在途请求；不积压、不自动重试、不补发停机期间的请求。
2. 至少 20 个对象按 1 分钟间隔调度；单对象超时或掉线不阻塞其他对象；关闭浏览器后后台继续运行。
3. 重启后配置、完整历史与统计一致；残缺或损坏行不导致全部历史丢失；裁剪后新记录保留且每个对象不超过配置上限。
4. Windows 对应架构构建产出 `.exe`，在无 Go / Python / Docker 的 Windows 环境双击可启动并打开本机面板；端口占用时回退，并展示实际 URL。
5. 在无 CDN / 外部资源网络的环境仍可展示配置和历史；远端探测的网络失败按规则记录。
6. 默认仅监听 `127.0.0.1`；读取接口、日志、错误详情和输出片段不泄露完整 Key；跨域页面不能修改配置或触发探测。
7. 平滑退出保存已完成结果；存储异常明确提示，不归因于被测接口。
